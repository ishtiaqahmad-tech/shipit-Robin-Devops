Who we are

Working Together as One Team

Team Robin is a four-member DevOps team taking part in the ShipIt Sprint activity. We plan our work in Jira, talk only on Slack, and keep all our code in one GitHub repository where every change goes through a branch, a pull request and a review before it reaches the live website.

How a change reaches the site

The Pipeline

From an idea on the Jira board to a live page, automatically.

01 // PLAN

Jira issue

Every task starts as a Jira issue and moves across the board from To Do to Done.

02 // BRANCH

Work on a branch

Nobody pushes to main. Each member works on a branch named after the Jira key.

03 // REVIEW

Pull request

Every change needs a pull request and at least one teammate's approval.

04 // CHECK

Automatic checks

check-site.sh looks for missing titles, broken links and oversized files.

05 // DEPLOY

GitHub Actions

When a pull request is merged, a workflow uploads the site and runs deploy.sh on the server.

06 // ALERT

Slack message

The result of every deploy is posted to the team alerts channel on Slack.

Safe, repeatable releases

Release & Rollback

Every version is kept, so going back takes seconds.

RELEASES

One folder per version

Each deploy creates a new folder named with the date, time and commit.

SWITCH

Instant go-live

The live site is a link called current that is switched to the new folder in one step.

VERSION

Stamped footer

The footer of each page shows the commit, who pushed it and when it was deployed.

ROLLBACK

One button back

rollback.sh points current to the previous release and logs who did it.

CLEAN-UP

Last five kept

Older releases are removed automatically so the server disk never fills up.

Always watching

Telemetry & Traffic

Two live pages refreshed by cron jobs on the server.

TELEMETRY

Server status

Uptime, load, memory, disk, Nginx state, the live release and the last five deploys, refreshed every minute.

TRAFFIC

Traffic report

A summary of visits to the site built from the Nginx logs every few minutes.
